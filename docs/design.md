# Codex 状态灯：最小设计

日期：2026-10-13

## 目标

制作一个 macOS 本地小应用，用一盏悬浮灯汇总本机多个 Codex 会话的状态。用户只需要一眼看到是否正在运行、是否需要介入。

## 界面与行为

- 一个竖排三灯组件，从上到下绿、黄、红，三盏灯始终可见；仅当前状态对应的灯点亮。macOS 26 原生液态玻璃胶囊外壳，可拖动，保持置顶，不抢键盘焦点。
- 黄灯呼吸：至少一个会话正在运行，且没有红灯状态。
- 绿灯常亮：所有会话空闲或已完成，或当前没有活跃会话。
- 红灯常亮：至少一个会话发出明确的等待确认、补充回答或错误事件。
- 汇总优先级：红 > 黄 > 绿。
- 菜单栏只提供状态说明、安装/更新 Hooks 和退出；不做会话列表、声音、通知、账户或网络服务。

## 实现方式

使用 Swift/AppKit 制作原生应用。Codex Hooks 将事件转换成各会话的状态文件，应用读取并汇总；文件只保存会话标识、状态和时间，不保存对话正文。只合并修改 Codex 的 Hooks，保留其他配置并备份。

启动或收到运行事件更新为黄灯；完成或明确空闲事件更新为绿灯；明确等待或错误事件更新为红灯。后续恢复运行可解除该会话的红灯，完成可转绿。会话结束移除记录；应用退出后不回放旧运行记录。可确认的客户端退出或会话结束用于清理，不根据持续时间猜测卡住。

接入以当前 Codex 实际提供的事件为准。实现前检查本机支持情况；若缺少补充回答或错误事件，必须说明覆盖限制，不根据回答文字或超时推测红灯。Hooks 首次信任由用户在 Codex 提示中完成，不写入信任状态。

## 验收

验证黄灯呼吸、红绿常亮与置顶拖动；用两个独立会话的事件验证红 > 黄 > 绿及恢复状态。验证 Hooks 保留其他配置，客户端重启后可接收真实事件。卸载时先移除配置，并为当前会话缓存保留临时空 Hook，避免删除脚本后拦截工具。
